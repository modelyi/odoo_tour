# TMS 技术架构思路

> 基于 Odoo 19/20 + SaaS + 小程序的旅行社管理系统
> 文档日期：2026-09-12

---

## 一、技术选型总览

| 层次 | 选型 | 说明 |
|------|------|------|
| **后端核心** | Odoo 19 社区版 | 当前稳定版，AI 功能已嵌入各模块 |
| **目标升级** | Odoo 20（2026年10月） | Agentic AI（自主执行型 AI），架构需预留升级空间 |
| **部署模式** | Odoo SaaS（多租户） | 支持多家旅行社共享基础设施、独立数据 |
| **前端-Web** | Odoo 原生 Web（OWL 框架） | 管理后台、计调操作、财务结算 |
| **前端-小程序** | 微信小程序（原生/Uni-app） | C 端商城 + 同业分销 + 导游报账 |
| **前端-移动端** | Odoo Mobile App（Odoo 20 全新设计） | 移动办公、审批、查询 |
| **AI 层** | Odoo 内置 AI + 自定义 AI Agent | 智能推荐、自动计调、财务预测 |
| **基础设施** | Docker + K8s + Nginx | 容器化部署、弹性伸缩 |

## 二、版本演进路线

### Odoo 19（2025年9月发布，当前基线）

Odoo 19 的核心升级方向：

| 能力 | 具体特性 | TMS 应用场景 |
|------|----------|-------------|
| **AI 助手** | AI 字段自动生成产品描述、邮件内容、任务摘要 | 线路描述自动生成、客户沟通自动摘要 |
| **AI 文档处理** | AI 分类规则，上传文件自动归档分配 | 合同/发票/行程单自动识别分类 |
| **AI 沟通** | 邮件对话历史摘要、附件阅读、回复建议 | 客户询价快速回复、历史沟通回顾 |
| **VOIP + AI** | 通话转录、翻译、实时摘要 | 客户电话记录自动生成跟进记录 |
| **移动端优先** | 响应式界面优化、平板适配 | 计调外勤操作、导游现场报账 |
| **会计增强** | ISO20022 银行标准、预扣税增强 | 跨境支付合规、多币种处理 |
| **Studio 增强** | 报表编辑器、电子表格透视 | 快速定制报表、利润分析 |
| **ESG 模块** | 碳足迹追踪 | 绿色旅游合规（远期） |

### Odoo 20（预计 2026年10月发布，目标版本）

Odoo 20 的核心跃迁——从"AI 助手"到"AI 自主执行"：

| 能力 | 具体特性 | TMS 应用场景 |
|------|----------|-------------|
| **Agentic AI** | AI Agent 可自主理解需求、决策、执行任务 | 自动派车派导、自动对账、智能并团 |
| **智能 CRM** | AI 自动评估线索概率、客户画像 | 自动识别高价值客户、预测成交率 |
| **AI 财务预测** | 基于实时数据的现金流/需求/采购预测 | 旺季资金预测、线路需求预判 |
| **重新设计移动端** | 全新移动体验 | 导游报账、计调外勤全功能移动化 |
| **智能库存预测** | 增强补货和预测 | 票务库存、酒店房量预测 |
| **低代码增强** | Studio 扩展视图定制、自动化构建器 | 业务人员自建报表和工作流 |
| **智能营销自动化** | 客户旅程自动化 | 老客户复购提醒、淡旺季精准推送 |

### 架构设计原则：Odoo 19 落地，Odoo 20 就绪

```
原则：
1. 基于 Odoo 19 开发，模块代码遵循 Odoo 20 升级规范
2. AI 功能分两层：Odoo 内置 AI（立即使用）+ 自定义 AI Agent（预留接口）
3. 自定义模块避免深度修改核心模型，优先扩展继承
4. 数据模型设计兼容 Agentic AI 的决策数据结构
```

## 三、SaaS 多租户架构

### 3.1 架构模式选择

针对旅行社 SaaS 场景，推荐**每租户独立数据库**模式：

```
┌─────────────────────────────────────────────────────┐
│                    Nginx / Traefik                   │
│              (SSL + 域名路由 + 负载均衡)               │
└──────────┬──────────────────────────┬────────────────┘
           │                          │
    ┌──────▼──────┐           ┌───────▼──────┐
    │  Odoo Node 1 │           │  Odoo Node 2 │
    │  (Workers×N) │           │  (Workers×N) │
    └──────┬──────┘           └───────┬──────┘
           │                          │
    ┌──────▼──────────────────────────▼──────┐
    │            PostgreSQL Cluster           │
    │                                        │
    │  ┌─────────┐ ┌─────────┐ ┌─────────┐  │
    │  │ DB-海螺  │ │ DB-XX社  │ │ DB-YY社  │  │
    │  │ (租户1) │ │ (租户2) │ │ (租户3) │  │
    │  └─────────┘ └─────────┘ └─────────┘  │
    └────────────────────────────────────────┘
```

### 3.2 为什么选"独立数据库"而非"多公司共享"

| 维度 | 多公司共享（单库） | 独立数据库（推荐） |
|------|-------------------|-------------------|
| 数据隔离 | 仅靠权限规则，有泄露风险 | 物理隔离，零风险 |
| 版本升级 | 所有租户同步升级 | 可按租户分批升级 |
| 定制灵活 | 共享模块集，无法差异化 | 每个租户可安装不同模块 |
| 数据迁移 | 极难拆分 | 独立备份/恢复/迁移 |
| 性能隔离 | 共享 CPU/RAM | 可按租户分配资源 |
| 合规 | 数据混存，审计困难 | 独立数据库，审计清晰 |
| 适用场景 | 集团内部子公司 | **SaaS 多客户（✓）** |

### 3.3 SaaS 租户生命周期管理

```
租户入驻流程（自动化）：
1. 注册/付费 → 触发 API
2. 自动创建 PostgreSQL 数据库（从模板库 clone）
3. 安装旅行社核心模块集
4. 初始化基础数据（结算方式、业务类型等）
5. 配置域名（xxx.tms-saas.com）+ SSL
6. 发送管理员账号邮件

租户运维：
- 独立备份策略（每日全量 + 实时 WAL 归档）
- 独立资源配额（Docker cgroups 限制 CPU/RAM）
- 统一监控面板（Prometheus + Grafana）
- 批量升级（蓝绿部署，灰度验证后全量切换）
```

## 五、AI 架构（Odoo 19 → 20 演进）

### 5.1 AI 能力分层

```
┌─────────────────────────────────────────────┐
│            Layer 3: Agentic AI              │

├─────────────────────────────────────────────┤
│            Layer 2: AI Assistant            │
│         (Odoo 19 内置 AI 助手)              │
│                                             │
│  • 线路描述自动生成                          │
│  • 客户沟通摘要                             │
```

### 5.2 TMS 场景 AI 应用规划

| 业务场景 | Layer 1 规则 | Layer 2 AI 助手 (v19) | Layer 3 Agentic AI (v20) |
|---------|-------------|----------------------|--------------------------|
| **线路设计** | 分类自动编号 | AI 生成行程描述、特色文案 | AI 根据市场数据推荐新线路 |
| **收客报价** | 价格规则自动计算 | AI 生成报价邮件、回复建议 | AI 自动评估成交概率、推荐策略 |
| **并团操作** | 关键字匹配规则 | AI 推荐最优并团方案 | AI 自主执行并团决策 |
| **派车派导** | 排班规则 | AI 推荐最优人选 | AI 自主调度、冲突自动解决 |
| **购物佣金** | 协议比例计算 | AI 异常检测（佣金偏离） | AI 预测购物收入、优化带店策略 |
| **收付款** | 认领匹配规则 | AI 辅助匹配未认领收款 | AI 自动认领 + 发起对账 |
| **财务分析** | 定时报表 | AI 生成分析报告摘要 | AI 预测现金流、预警异常 |
| **客户服务** | FAQ 知识库 | AI 聊天机器人、通话摘要 | AI 自主处理常见投诉、升级复杂问题 |

### 5.3 自定义 AI Agent 接口预留

```python
# 为 Odoo 20 Agentic AI 预留的 Agent 接口框架
class TourAgentMixin:
    """
    旅行社 AI Agent 基类
    - 定义 Agent 可观测的数据范围
    - 定义 Agent 可执行的动作边界
    - 定义 Agent 决策的审计日志
    """
    
    # Agent 可读取的模型
    _agent_readable_models = [
        'tour.line', 'tour.plan', 'tour.plan.reg',
        'tour.guide', 'fleet.vehicle', 'res.partner'
    ]
    
    # Agent 可执行的动作（需审批的动作标记为 require_approval）
    _agent_actions = {
        'auto_merge_plan': {'require_approval': False, 'desc': '自动并团'},
        'assign_guide': {'require_approval': True, 'desc': '派导'},
        'assign_vehicle': {'require_approval': True, 'desc': '派车'},
        'auto_claim_payment': {'require_approval': False, 'desc': '自动收款认领'},
        'generate_itinerary': {'require_approval': False, 'desc': '生成行程'},
    }
    
    # 每次 Agent 动作记录审计日志
    def _log_agent_action(self, action, params, result, confidence):
        """记录 AI Agent 的每次决策和执行"""
        self.env['tour.agent.log'].create({
            'action': action,
            'params': json.dumps(params),
            'result': json.dumps(result),
            'confidence': confidence,
            'user_id': self.env.user.id,  # Agent 关联的系统用户
        })
```

## 八、关键决策点（待确认）

| # | 决策项 | 选项 | 建议 |
|---|--------|------|------|
| 1 | Odoo 版本 | 17/18 vs 19 vs 等20 | **Odoo 19**（已稳定，AI 功能丰富，为 20 铺路） |
| 2 | SaaS 模式 | 自建 vs Odoo.sh vs Odoo Online | **自建 SaaS**（定制灵活，成本可控） |
| 3 | 数据库隔离 | 共享库 vs 独立库 | **独立库**（数据安全，升级灵活） |
| 4 | 小程序框架 | 原生 vs Uni-app vs Taro | **Uni-app**（跨端：微信/支付宝/H5） |
| 5 | 小程序数量 | 4个独立 vs 1个多角色 | **1个小程序，按角色分视图**（维护成本低） |
| 6 | AI 模型 | Odoo 内置 vs 自建 vs 混合 | **混合**（内置 AI 先用 + 自建 Agent 补充） |
| 7 | 部署平台 | 阿里云 vs 腾讯云 vs AWS | 待定（考虑小程序生态，腾讯云可能有优势） |
| 8 | 支付 | 微信支付 vs 支付宝 vs 聚合 | **聚合支付**（微信 + 支付宝 + 银行卡） |

## 九、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| Odoo 20 延期发布 | 升级计划推迟 | 基于 19 独立运行，20 非阻塞依赖 |
| Agentic AI 不成熟 | AI 功能不达预期 | Layer 1 规则引擎兜底，AI 渐进启用 |
| SaaS 多租户性能 | 租户增多后变慢 | 预留水平扩展能力，大租户独立节点 |
| 小程序审核 | 上线时间不可控 | 提前申请资质，H5 版本作为备选 |
| 数据迁移 | 旧系统数据丢失 | 先迁移再并行运行，保留旧系统只读 |
| Odoo 社区版限制 | 部分功能仅企业版 | 评估 Studio/Accounting 等是否需企业版 |
