# TMS 功能优先级矩阵

> 基于易途 V7 系统 247 项菜单，按 **业务价值 × 技术成本** 分类
> 日期：2026-09-12
> 优先级定义：P0（必做）→ P1（应做）→ P2（可做）→ P3（远期/按需）

---

## 优先级判定规则

```
             技术成本
             低        中        高
业  高    │  P0      │  P0      │  P1
务       │ Quick Win │ 核心投入  │ 战略投入
价  ─────┼──────────┼──────────┼──────────
值  中    │  P1      │  P2      │  P2
         │ 低垂果实  │ 计划推进  │ 审慎评估
    ─────┼──────────┼──────────┼──────────
    低    │  P2      │  P3      │  P3
         │ 填充功能  │ 远期规划  │ 暂不实施
```

- **P0（必做）**：业务价值高，无论技术成本高低都必须优先实现。核心业务闭环必需。
- **P1（应做）**：业务价值高+高成本，或业务价值中+低成本。重要但可稍后。
- **P2（可做）**：业务价值中+中高成本，或业务价值低+低成本。锦上添花。
- **P3（远期）**：业务价值低+中高成本。按需或远期规划。

## 关键决策建议

| 决策点 | 建议 | 理由 |
|--------|------|------|
| 并团操作实现方式 | P0 投入，用向导（Wizard）简化 | 业务核心但逻辑复杂，需充分设计 |
| 购物佣金引擎 | P1 投入，规则引擎+可配置 | 计算规则多样，需灵活配置 |
| 收款认领流程 | P1 投入，参考 Odoo 会计对账 | 可复用 Odoo 原生能力 |
| 审批流程 | P1 投入，扩展 Odoo 审批 | Odoo 自带审批流，扩展即可 |
| 同业分销 | P2，先用门户（Portal）实现 | Odoo 门户模块可快速搭建 |
| 小程序商城 | P3，先验证 C 端需求 | 投入大，需先确认商业模式 |
| 车队管理 | P2，评估是否独立系统 | 可作为独立子系统，按需集成 |
| 支付宝费控 | P3，按需实现 | 非核心功能，仅部分客户需要 |

## 未覆盖菜单说明

以下 27 项易途菜单未纳入优先级矩阵，原因如下：

| 类别 | 菜单 | 原因 |
|------|------|------|
| 系统内部 | 菜单维护、参数维护、报表管理 | 后台管理功能，不对用户暴露 |
| 重复入口 | 认领查询/认领平账（与收款认领重复） | 功能重复，合并实现 |
| 特殊场景 | 公司合并、注册新公司 | SaaS 平台管理功能，归入 tour_saas |
| 低频操作 | 删除付款记录、人员移动 | 低频管理操作 |
| 配置类 | 二维码设置、综合查询配置、打印账号 | 辅助配置，按需实现 |
