> **一句话定位**：一套面向中小旅行社/地接社的**单店标准产品**（一旅行社一实例），在 Odoo 20 + Odoo Mates 财务底座上，用 `ta_*` 自研模块覆盖"线路班期 → 报价报名 → 收款认领 → 计调 → 单团核算 → 导游报账与佣金"**核心业务闭环**，架构预留 SaaS 演进。

---

## 1. 产品定位

### 1.1 与旧 PRD 的关系

旧 PRD（v19）定位为"SaaS 化旅行社 ERP，支持多租户、50+ 租户"。本 V20 规划做出三点收缩与一项坚持：

| 维度 | 旧 PRD（v19） | 本规划（V20） | 理由 |
|------|--------------|--------------|------|
| 交付形态 | SaaS 多租户平台 | **单店标准产品**，架构预留 SaaS | CR-01 已将多租户移出范围；tms19 运营数据证明 SaaS 相关能力零使用 |
| 功能面 | 全链路 14 模块 292 人天（含 B2B/票务/AI/小程序） | **核心闭环 MVP**，长尾分批 | 19 端使用热度集中在班期/收款认领/单团核算三处热区，其余模块基本无人用 |
| 代码来源 | 在 tms19 存量上迭代 | **完全新写**（`ta_*` 前缀），存量仅作规格参考 | 用户裁定不做迁移升级；旧代码携带源系统遗留字段与第三方 fork 债务 |
| 财务底座 | 自研 tour_accounting 记账对接 | **om 全家桶 + l10n_cn 直接承载凭证/总账** | tour20 已装 84 模块，会计栈以 om 为基础 |

### 1.2 目标客户

- 中小组团社/地接社，10–30 人同时在线规模（沿用旧 PRD 约束条件，与 tms19 生产实测负载一致）；
- 有专职出纳、会计、计调、导游调度岗位划分（这是收款三步闭环、三段审核等内控功能的目标场景）；
- 使用人民币核算、适用中国会计准则（l10n_cn 科目模板），部分客户涉及差额征税。

### 1.3 交付模式

一客户一实例：标准模块包（`ta_*` + om + l10n_cn + 基座配置）+ 一键部署脚本（compose + Makefile，参照 `c-系统实现/odootour/` 现行工程化），新旅行社可在半天内完成开库、装模块、期初建账（期初建账流程参考 BS-16）。

## 2. 角色与权限

沿用旧 PRD 的 8 角色画像，按单店形态裁剪：**删除"同业伙伴""C端游客"两类外部角色**（B2B 门户与小程序商城均出 MVP 范围），门户（portal）能力仅保留导游移动端自助报销/查佣金一项，其余待批 3 评估。

| 角色 | 一句话职责 | 关键权限设计 |
|------|-----------|-------------|
| 销售/外联 | 线路查询、快速报价、下单报名 | 只能认领/变更本团队的收款申请，不能审核 |
| 计调 | 资源预订、班期排期、并团、成本控制 | 维护班期与费用预算，提交三段审核第 1 段 |
| 出纳 | 银行到账登记 | 执行收款闭环步骤 1"登记"，与认领、审核互斥 |
| 会计/财务经理 | 收款认领审核、凭证、单团核算口径 | 执行步骤 3"审核"；唯一可查全量利润口径的角色之一 |
| 导游 | 带团费用录入、报账、借款申请 | 移动端自助；只见自己的借款/报账/佣金 |
| 管理层 | 经营报表、审批 | 审批流终段；单团毛利与现金看板 |
| 系统管理员 | 主数据、参数、权限配置 | 配置 res.config.settings；不参与业务单据四眼操作 |

**内控硬约束（继承 tms19 已验证规则）**：收款闭环"登记人 ≠ 认领人 ≠ 审核人"系统级拦截（BS-06 AC-05）；同一单据同一动作幂等防重。

## 3. 核心闭环业务流（MVP）

六个环节、一条主线。各环节业务规则以对应 BS 为素材来源，新产品按其**结论**实现、按新口径表述，不复用旧模块与字段名。

### 3.1 线路 / 班期（素材：BS-01）

- 对象：**线路产品**（行程明细、多价格体系：成人/儿童/单房差/同订价）→ **班期**（发团计划：日期、名额、成团线）→ **并团**（多班期/散客并到同一名实团）。
- 状态机：线路 `草稿 → 在售 → 停售`；班期 `计划 → 报名中 → 确认成团 → 发团 → 结算完成 / 取消`。
- 业务模式码沿用 15 项枚举语义（团队输单/团期计划/散客单组/散客并团/内部流转/产品计划/关键字并团/组团团队/组团散客/代订项目/自由行/共享协议报名等，出处 `tour_base/models/constants.py` 对应的 BS-02 §5），V20 在 `ta_base` 中以**新命名重定义**，逐码在新文档给出映射表。

### 3.2 报价与订单报名（素材：BS-02）

- 对象：**团队订单**（名单、应收计划）/ **散客订单**（按人报名，可并团）。
- 报价 = 班期价格体系 + 人数结构 → 生成应收计划（分期付款期次）。
- 状态机：订单 `草稿 → 已确认 → 已派计调 → 行程中 → 待结算 → 已结算 / 取消`；确认时校验班期余位与成团线。

### 3.3 收款认领三步闭环（素材：BS-06；账号口径 BS-05）

1. **收款登记**（出纳）：录入银行到账流水，状态"待认领"；支持批量导入。
2. **收款认领**（业务员/计调）：将到账关联到订单/团队，允许拆分、合并认领。
3. **认领审核**（会计/财务经理）：通过后自动核销应收，回写团队已收/未收汇总。

未完成认领的到账挂"未认领池"；认领错误走反审核 + 红冲，不允许直改。

### 3.4 计调派工（素材：BS-03）

- 对象：**预订安排**（用车/用房/用餐/门票/地接等资源条目）挂到实团，形成成本预算；导游安排、领队安排。
- 计调条目确认后按业务模式生成应付（供应商）与费用预算，进入单团核算的成本侧。

### 3.5 单团核算（素材：BS-19 口径裁定、BS-14 收入成本确认）

- 对象：**单团损益表**——一团一账户，实时汇总该团已审核收款（收入）、计调成本条目与报账费用（成本）。
- **毛利口径（唯一权威）**：`cost_net_total = cost_total ÷ (1 + r)`；`profit = income_total − cost_net_total`，即差额征税·不含税口径；含税口径单列展示字段 `profit_tax_incl`，由"成本含税拆分"开关控制、**互斥防双重扣减**（继承 BS-19 裁定）。
- 凭证层直接落 om 账套（account.move），单团核算只做业务归集与口径展示，不自建第二套总账。

### 3.6 导游借款-报账-佣金（素材：导游端到端报告、BS-08）

- **借款**：导游出发前申请备用金 → 审批 → 发放（挂其他应收款-导游借款）；逾期提醒。
- **报账**：移动端录入带团费用 + 票据 → 审核 → 生成费用并计入所属团成本。
- **佣金/结算**：带团补贴 + 购物返佣分成（分成规则批 2）计算佣金单；**税后净额可冲抵未还借款**（BS-08 AC-18）；已代扣个税在下次代扣时抵扣或提示退税；导游对账确认环节在 19 端未实现，V20 列为批 1 收口项。

### 3.7 第二批能力（明确不在 MVP）

购物返佣分成完整链路、差额征税申报底稿、三段审核（计调→财务→管理层对单据的分级审核）全量铺开、单团利润多维报表。

| SaaS 多租户运行时 | 本期不实施，仅按 §5 三原则预留 |

## 5. 架构预留 SaaS 三原则

1. **company_id 全挂 + record rule**：所有业务单据模型带 `company_id` 并纳入记录规则过滤；任何查询不得写死单公司假设。将来若走"一库多公司"路线，只是放开配置而非改模型。
2. **以复制实例为演进方式，不做共享 schema 技巧**：多客户扩展 = 标准模块包复制到新实例 + 一键部署；不引入跨租户中间件、不做 tour_saas 式共库分区。此路线与将来需要时再演进多租户不冲突。
3. **配置收敛到 res.config.settings**：业务开关（成本含税拆分、审核级数、佣金规则参数等）全部走设置项与租户数据，不硬编码单店假设、不开放给普通用户改的 XML 里放业务参数。

## 6. 与 tms19 存量资产的关系

| 资产 | 处置 |
|------|------|
| tms19 生产库 `tms`（tms-odoo/tms-db） | 继续独立运行，**不迁移数据、不停机切换**；作为业务规格的历史证据（使用热度数据出处） |
| `c-系统实现/tms-platform/addons/tour_*`（23 模块） | **只读规格参考**：业务规则、状态机、边界处理经验从这里核对；代码不搬运 |
| `~/odoo20tour/cust_addons`（35 个 addons20 模块） | 留在挂载位但**不装载入任何库**；与 tour_* 同等参考地位（`ODOO_PIN.md` 已有记录） |
| BS-01..BS-19 业务规格 | 其**裁决结论**（如 BS-19 毛利口径、BS-06 AC-05）为 V20 的业务规则素材；实施阶段逐篇做 20.0 口径改版 |
| TDS-30/31/32 与《迁移与升级计划》 | 已废止归档，仅存档 |
