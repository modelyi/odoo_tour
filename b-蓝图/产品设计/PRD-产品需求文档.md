# TMS 产品需求文档（PRD）

> 产品名称：TMS 旅行社管理系统
> 版本：1.0
> 日期：2026-09-12
> 基于：易途 V7 系统调研（247项菜单、12种业务模式、7个子产品）

---

## 1. 产品愿景

**一套基于 Odoo 的 SaaS 化旅行社 ERP，覆盖"产品研发→销售→计调→财务→决策分析"全链路，支持多租户、多业务模式、移动端协同。**

---

## 2. 目标用户

| 角色 | 核心需求 | 使用频率 |
|------|----------|----------|
| **销售/外联** | 线路查询、快速报价、下单报名、客户跟进 | 每日高频 |
| **计调** | 资源预订（房/车/导/票/餐）、并团操作、行程安排、成本控制 | 每日高频 |
| **财务** | 收付款登记、收款认领、往来对账、发票管理、单团核算、佣金计算 | 每日高频 |
| **导游** | 带团费用录入、报账提交、借款申请（移动端） | 出团期间 |
| **管理层** | 经营报表、利润分析、业绩统计、审批 | 每日/周 |
| **同业伙伴** | 产品浏览、在线下单、对账结算（门户/小程序） | 按需 |
| **C端游客** | 线路浏览、在线下单、支付（小程序商城） | 按需 |
| **系统管理员** | 用户权限、审批流程、业务参数配置 | 按需 |

---

## 3. 核心价值主张

| 价值点 | 说明 |
|--------|------|
| **全业务覆盖** | 对标易途 V7 的 247 项功能，覆盖组团、地接、散客、代订、自由行等 12 种业务模式 |
| **SaaS 多租户** | 独立数据库隔离，多家旅行社共享基础设施、独立数据、按需付费 |
| **移动端协同** | 小程序矩阵（C端商城 + 同业分销 + 导游报账 + 百推），随时随地办公 |
| **AI 增强** | 从规则引擎（v19）到 Agentic AI（v20），逐步实现智能派车派导、自动对账、财务预测 |
| **低门槛上线** | 标准化模板 + 自动化租户入驻，新旅行社可快速启用 |

## 5. 成功指标

| 指标 | 目标值 | 衡量方式 |
|------|--------|----------|
| **功能覆盖率** | Phase 1 覆盖易途核心功能 ≥60%，全量 ≥85% | 菜单功能对标 |

| **用户满意度** | NPS ≥ 40 | 季度用户调研 |
| **操作效率** | 常规操作 < 2 秒响应 | 系统监控 |
| **数据准确性** | 财务核算误差 < 0.01% | 对账校验 |
| **租户上线时间** | 新租户 ≤ 1 天完成初始化 | SaaS 管理平台统计 |
| **移动端覆盖** | 导游报账、同业下单 100% 移动化 | 功能覆盖检查 |
| **系统可用性** | SLA ≥ 99.5% | 监控告警 |

## 6. 约束条件

| 约束 | 说明 |
|------|------|
| **Odoo 版本** | 基于 Odoo 19 社区版开发，架构预留 Odoo 20 升级空间 |
| **SaaS 多租户** | 每租户独立数据库，Docker + K8s 容器化部署 |
| **小程序** | Uni-app 框架，1 个小程序按角色分视图（C端/同业/导游/客服） |
| **AI 分层** | Layer 1 规则引擎 → Layer 2 AI 助手（v19）→ Layer 3 Agentic AI（v20） |
| **社区版限制** | 部分功能（Studio、完整会计）需评估是否需企业版 |
| **首期不含在线支付** | 收款以线下确认为主，小程序阶段接入微信支付 |
| **用户规模** | 单租户 10-30 人同时在线，平台支持 50+ 租户 |
| **数据迁移** | 需支持从易途系统导入历史数据 |
| **多语言** | 首期中文，预留中/英/泰多语言扩展 |

## 7. 业务流程主线

```
产品研发（线路设计、分类、行程、定价）
    ↓
产品销售（门市收客 / 同业分销 / 小程序商城）
    ↓
订单确认（报名、并团、审批）
    ↓
计调操作（预订资源、派车派导、成本控制）
    ↓
出团执行（接待、购物佣金记录）
    ↓
财务结算（收款、付款、对账、发票、佣金计算）
    ↓
决策分析（报表、利润分析、业绩统计）
```
