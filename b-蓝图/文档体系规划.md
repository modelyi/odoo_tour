## 一、文档体系总览

### 1.1 体系结构

```
TMS 文档体系
├── a-调研/                    # 研究阶段（已完成）
│   ├── 需求文档                # 业务需求采集
│   ├── 易途系统功能调研         # 竞品调研
│   ├── Odoo功能映射方案         # 技术可行性分析
│   ├── 易途系统表单字段文档      # 字段级调研
│   └── et_data/               # 调研原始数据
│
├── b-蓝图/                    # 蓝图设计阶段（进行中）
│   ├── product/               # 产品层文档（PRD、路线图、规格）
│   ├── architecture/          # 技术层文档（架构、模型、API）
│   ├── testing/               # 测试层文档（计划、用例）
│   └── operations/            # 运维层文档（部署、运维）
│
├── c-系统实现/                 # 开发实现阶段
│   └── tms-platform/          # 代码仓库
│       ├── addons/            # Odoo 自定义模块
│       ├── .subagents/        # 协作角色定义
│       └── README.md          # 开发指南
│
└── d-交付验收/                 # 交付验收阶段
    ├── UAT测试报告             # 验收测试记录
    ├── 发布说明                # 版本发布记录
    └── 用户手册                # 最终用户文档
```

### 1.2 文档层级关系

```
产品愿景（Product Vision）
    ↓
产品路线图（Product Roadmap）
    ↓
产品需求文档 PRD（Product Requirements Document）
    ↓
┌───────────────┬───────────────┬───────────────┐
│ 功能规格说明   │ 技术架构设计   │ 测试计划      │
│ (Functional   │ (Technical    │ (Test Plan)   │
│  Spec)        │  Architecture)│               │
└───────┬───────┴───────┬───────┴───────┬───────┘
        ↓               ↓               ↓
    用户故事        数据模型/API     测试用例
    (User Stories)  (Data Model/    (Test Cases)
                     API Spec)
        ↓               ↓               ↓
    验收标准        代码实现        测试执行
    (Acceptance     (Code)         (Execution)
     Criteria)
```

## 四、文档模板与规范

### 4.1 文档命名规范

- 产品层：`PRD-{序号}-{模块名}.md`（如 `PRD-01-线路管理.md`）
- 技术层：`{序号}-{文档类型}.md`（如 `03-数据模型设计.md`）
- 测试层：`测试用例/TC-{序号}-{模块名}.md`
- 运维层：`{序号}-{文档类型}.md`
- 交付层：按类型命名

### 4.2 文档结构模板

#### PRD 模板

```markdown
# PRD-{序号}: {模块名}

> 版本：vX.Y | 日期：YYYY-MM-DD | 作者：xxx

## 1. 概述
## 2. 用户故事
## 3. 功能需求
## 4. 非功能需求
## 5. 业务规则
## 6. 验收标准
## 7. 依赖与约束
## 8. 附录
```

#### 技术设计文档模板

```markdown
# {文档名}

> 版本：vX.Y | 日期：YYYY-MM-DD | 作者：xxx

## 1. 背景与目标
## 2. 架构设计
## 3. 详细设计
## 4. 接口定义
## 5. 数据模型
## 6. 安全考虑
## 7. 性能考虑
## 8. 部署方案
```

#### 测试用例模板

```markdown
# TC-{序号}: {模块名}

> 版本：vX.Y | 日期：YYYY-MM-DD | 作者：xxx

## 测试范围
## 前置条件
## 测试用例列表

| # | 用例名 | 步骤 | 预期结果 | 优先级 |
|---|--------|------|----------|--------|

## 测试数据
## 测试环境
```

### 4.3 文档维护规则

1. **版本控制**：所有文档纳入 Git 管理，重大修改记录变更日志
2. **评审机制**：P0/P1 文档需经相关方评审后定稿
3. **更新触发**：需求变更、架构调整、版本发布时同步更新文档
4. **归档规则**：已废弃文档移入 `archive/` 目录，保留历史版本
