## 1. "人"维度扩展到全员（hr.employee）的财务/税务影响

### 1.1 导服费定性：工资薪金 vs 劳务报酬（核心判断）

**结论：归入 hr.employee ≠ 必然按工资薪金处理。** hr.employee 只是"人员档案"维度，不改变"用工关系的法律性质"。必须新增一个判定字段：

> **新增字段 `employment_type`（用工关系/结算类型）**：
> - `labor_contract`（劳动合同）→ 全职雇员，导服费/带团提成 = **工资薪金所得**
> - `service_contract`（劳务协议/挂靠）→ 兼职/挂靠导游，导服费 = **劳务报酬所得**
> - `temporary`（临时合作）→ 按次结算，= **劳务报酬所得**

| 判定依据 [个税法] | 工资薪金 | 劳务报酬 |
|---|---|---|
| 法律关系 | 劳动合同，存在雇佣/隶属关系 | 劳务协议/合作协议，独立劳务 |
| 社保 | 公司缴纳社保 [社会保险法] | 无社保缴纳义务 |
| 个税预扣 | 按月累计预扣，3%-45% 七级超额累进，月减除 5000 + 专项附加 | 按次预扣，减除 800（≤4000）或 20%（>4000），20%-40% 三级累进 |
| 年度 | 并入综合所得汇算 | 并入综合所得汇算（同一税目口径） |
| 会计科目 | 贷 **2211 应付职工薪酬** | 贷 **2241.02 其他应付款—导游分成** |
| 代扣科目 | 2221.05 应交个人所得税 | 2221.05 应交个人所得税 |

**对现状的影响**：现状佣金按劳务报酬 20%-40% 累进预扣，对应的是"非雇员"口径。**只要劳务协议导游在 hr.employee 上标记为 `service_contract`，现有预扣口径完全保留，不做任何变更。** 只有真正签了劳动合同的全职导游才切换为工资薪金口径，且必须同时满足：
- 已缴社保（否则存在事实劳动关系但未缴社保的合规缺口，见 §6）
- 并入 payroll 按月申报，而非按团按次预扣

**合规红线**：不得"同一个人既按工资薪金又按劳务报酬"混扣。同一自然人在同一公司应只有一种用工关系定性 [个税法-所得项目划分]。

### 1.2 员工（计调/销售/行政）vs 导游 的记账差异

| 维度 | 导游（劳务/劳动合同） | 员工（计调/销售/行政） |
|---|---|---|
| 费用归集科目 | **6401.xx 主营业务成本**（挂团 analytic，一团一核算） | **6601 销售费用 / 6602 管理费用**（挂部门/项目 analytic，一般不挂团） |
| 是否挂团 | 挂 tour.plan（出团成本） | 一般不挂团；为某团出差时可选挂团 |
| 个税 | 导服费需代扣（工资薪金或劳务报酬） | 报销是**费用补偿，不征个税**；但以现金形式发放的补贴/津贴须并入工资计税 [个税法] |
| 差额征税 | 导服不可扣除；代付第三方车/餐/门票/房可扣除 | 自身差旅费**不可扣除**（见 §4） |
| 借款科目 | 1221.01（团借款） | 1221.02 备用金 / 1221.03 代付 |
| 冲抵凭证 | 借 6401 / 贷 1221.01 | 借 6601/6602 / 贷 1221.02 或 2241.06 |

**关键区分原则**：费用进"成本（6401，挂团）"还是"期间费用（6601/6602）"，由**费用的受益对象**决定——构成某团旅游服务直接成本的进 6401 挂团；属公司管理/销售职能的进期间费用。**与报销人是导游还是员工无关，与费用用途有关。**

## 2. 借款冲抵链路的科目通用性

### 2.1 结论

- **1221.01 其他应收款—导游借款 → 改名"其他应收款—员工借款"**（导游是员工的一种）。
- **全员借款共用同一科目 1221.01，不按员工类型（导游/计调/销售）拆分。** 科目按"经济实质"分类（借款/备用金/代付），人的维度由 `partner_id`（hr.employee 关联联系人）+ `analytic_distribution` 区分。
- 科目表已预置 1221.02 备用金、1221.03 员工代付，无需新建。

### 2.2 科目映射（借款场景）

| 场景 | 借方 | 贷方 | 合规依据 |
|---|---|---|---|
| 团借款放款（导游出团预支） | 1221.01 员工借款 | 1002 银行 | [CAS 22-金融工具] |
| 员工备用金拨付 | 1221.02 备用金 | 1002 银行 | [CAS 22] |
| 报账冲抵（借 成本/费用 / 贷 借款科目） | 6401.xx / 660x | 1221.01/02 | [CAS 1-成本归集] |
| 差额补款（报账>借款） | — | 1002（贷） | [支付结算办法] |
| 差额退款（报账<借款） | 1002（借） | — | [支付结算办法] |

### 2.3 迁移建议

- `tour.guide.loan.guide_id (Many2one tour.guide)` → **新增 `employee_id (Many2one hr.employee)`** 为主维度；`guide_id` 改为可空冗余字段（迁移期兼容，或由 `employee_id` 反向推导）。
- 历史 1221.01 余额不需换科目（仅改科目 name），借贷方向、partner、analytic 均不变，冲抵链路不断。
- 存量数据：`tour.guide` 增 `employee_id` 字段，导游档案与员工档案建立 1:1 关联（迁移脚本补齐）。

## 3. 纯报销（无借款）的记账口径

### 3.1 结论：两段式（先挂应付、再付款）

> 员工垫付 → 公司报销，**不直接** 借费用/贷银行，而是：

```
审核通过（生成凭证）：借 费用科目 / 贷 2241.06 其他应付款—员工代付
出纳付款（生成付款单）：借 2241.06 / 贷 1002 银行存款
```

| 方案 | 分录 | 内控 | 推荐 |
|---|---|---|---|
| A 直接报销 | 借 费用/贷 1002 | 审核=付款，无分离 ❌ | ✗ |
| **B 两段式** | 审核借费用/贷 2241.06 → 付款借 2241.06/贷 1002 | 审批≠付款，账龄可跟踪 ✓ | ✓ |

**理由**：
- 符合"制单/审核 ≠ 出纳付款"不相容职务分离 [内控-职务分离]
- 2241.06 其他应付款—员工代付 已存在于科目表，可跟踪"已审未付"账龄
- 与 Odoo 原生 hr.expense 链路一致，便于后续接入批量付款/银行对账
- 与现有借款"审核→放款"两段式思路统一

**注意**：员工"垫付"（公司尚未付给员工）走 1221.03 员工代付（资产）；员工"已代付、公司应付款"走 2241.06（负债）。当前报销场景默认后者。

## 4. 差额征税可扣除的合规

### 4.1 现状规则的偏差（需修正）

财税[2016]36号附件2 旅游服务差额扣除项目：
✅ 住宿费、✅ 餐饮费、✅ 交通费、✅ 门票费、✅ **签证费**、✅ 支付给其他接团旅游企业的旅游费（地接费）

| 现状 expense_type | 现状 deductible | 合规结论 |
|---|---|---|
| vehicle 车费 | ✅ 可扣除 | ✅ 正确（交通费） |
| meal 餐费 | ✅ 可扣除 | ✅ 正确 |
| ticket 门票 | ✅ 可扣除 | ✅ 正确 |
| hotel 房费 | ✅ 可扣除 | ✅ 正确（住宿费） |
| guide 导服费 | ❌ 不可扣除 | ✅ 正确 |
| other 其他 | ❌ 不可扣除 | ✅ 正确 |
| **签证费** | **缺失** | ⚠️ **需新增类型，应可扣除** |
| **地接费** | **缺失** | ⚠️ 走供应商对账链路（2202.01），不在此链路，但统一后需保留 |

### 4.2 全员报销下的可扣除判断（关键）

差额扣除的本质是：**"为旅游服务购买方发生、支付给第三方的直接成本，且取得合规发票"**，与"报销人是导游还是员工"无关。但必须满足两个条件，否则不可扣除：

1. **成本性质** ∈ 可扣除集（车/餐/门票/房/签证/地接）
2. **归集方向** ∈ 6401 主营业务成本且挂团 analytic（构成某团旅游成本）

**合规红线**：
- 员工（计调/销售/行政）的**自身差旅费**（出差交通/住宿/餐饮）即使发票是住宿/餐饮，因进 6601/6602 期间费用、不构成"支付给第三方为游客提供的服务"，**一律不可差额扣除** [财税2016-36号 + 自身发生的差旅费不可扣除]。
- 反之，员工"为某团垫付的第三方费用"（如销售代购某团门票）若挂团进 6401，则可扣除——判断标准是**费用性质与归集**，不是报销人身份。

### 4.3 修正后的 deductible 规则

> `deductible = (expense_type ∈ {vehicle, meal, ticket, hotel, visa, 地接}) AND (成本科目.account_type ∈ expense_direct_cost 且挂团) AND (invoice_no 非空)`

- 现有 `@api.onchange` 的 `deductible = expense_type in (vehicle/meal/ticket/hotel)` 需改为上述复合判断。
- 现有 `_check_deductible_invoice` 约束保留（可扣除必须填发票号）。

## 5. 内控规则设计

### 5.1 保留并扩展

| 规则 | 现状 | 全员化调整 |
|---|---|---|
| R-27 三方分离 | 借款人≠审批人≠放款人 | 保留；**扩展为"报销人≠审批人≠付款人"**，并新增"财务审核人"角色，四角色分离 |
| R-29 30天报账预警 | 放款+30天 | 保留（借款）；**纯报销新增"费用发生+30天提交"时限** |
| R-30 未冲抵禁新借 | 有未冲抵借款禁新借 | 保留，按 hr.employee 维度判断；导游团借款与员工备用金**分池**判断 |
| R-31 报账归团 | 报账支出挂团 | 导游报账挂团保留；员工费用按部门/项目归集，不强制挂团 |
| R-33 回团7天报账 | 超期扣导服费 | 保留（仅劳动合同/劳务协议导游适用） |

### 5.2 新增

1. **分级限额 [内控-授权审批]**：按职级/角色设单笔+月度借款限额，超限升级审批。
   - 导游：单团借款 ≤ 该团成本预算（R-28 现状 LoanRate 限额沿用）
   - 员工备用金：默认单笔 ≤ ¥5,000、月度累计 ≤ ¥20,000，可配置；超限财务总监特批
2. **三审分离 [内控-职务分离]**：报销单设"业务审批人（部门主管）→ 财务审核人（会计）→ 付款人（出纳）"三个角色，不得兼任；系统强制校验。
3. **金额阈值审批矩阵**：如 ¥2,000 以下部门主管、¥2,000~¥10,000 财务经理、¥10,000 以上财务总监。
4. **发票要素校验 [财税2016-36号]**：报销发票抬头=公司、税号正确；可差额扣除项逐笔关联发票号。
5. **离职锁定 [内控-资金管理]**：hr.employee 离职时冻结借款权限，未冲抵借款/未报销强制结清或转办。

## 6. 风险清单

| # | 风险 | 等级 | 影响 | 缓解措施 | 依据 |
|---|---|---|---|---|---|
| 1 | 导服费个税定性错误（归入员工却继续按劳务报酬，或反之） | 🔴 高 | 代扣义务履行错误 → 补税+滞纳金+罚款 | employment_type 字段强制分流；同一自然人单一定性；全职导游切换工资薪金需同步 payroll | [个税法] |
| 2 | 导游归入员工被认定事实劳动关系 → 社保补缴 | 🔴 高 | 补缴社保+滞纳金 | 劳动合同导游必须缴社保；挂靠导游签劳务协议、明确独立劳务性质 | [社会保险法] |
| 3 | 员工差旅费误入差额征税扣除 | 🔴 高 | 少缴增值税 → 追缴+罚款 | 可扣除=性质+挂团+发票三条件；期间费用一律不可扣除 | [财税2016-36号] |
| 4 | 签证费可扣除项缺失 | 🟡 中 | 多缴增值税（利润受损） | 补签证费 expense_type + deductible | [财税2016-36号] |
| 5 | 应付职工薪酬(2211)与导游分成(2241.02)混用 | 🟡 中 | 职工薪酬报表失真、个税申报错误 | 按 employment_type 强制分流科目 | [CAS 9] |
| 6 | 多公司（company）隔离失效，跨公司借款/报销串账 | 🟡 中 | 关联交易/资金混淆 | 借款/报账单强制 company_id 继承员工所属公司；跨公司走 1221.04/2241.05 内部往来 | [CAS 37] |

| 8 | 报销人=审批人=付款人职责未分离 | 🟡 中 | 资金安全 | 系统级四角色分离校验 | [内控-职务分离] |
| 9 | 员工报销现金补贴未并入工资计税 | 🟡 中 | 个税漏缴 | 现金补贴走 payroll，不入报销 | [个税法] |

## 7. 需调整的现有链路（dev-odoo 实现要点）

1. **数据模型**：`tour.guide.loan.guide_id` / `tour.guide.real.pay.guide_id` 增加 `employee_id (Many2one hr.employee)` 为主维度；`tour.guide` 增 `employee_id` 关联 + `employment_type`（劳动关系类型）。
2. **科目改名**：1221.01 name 由"导游借款"改"员工借款"（`ACCOUNT_GUIDE_LOAN` 常量名同步改为 `ACCOUNT_EMPLOYEE_LOAN`，编码不变 1221.01）。
3. **纯报销放开**：`tour.guide.real.pay.action_audit` 去掉 `if not rec.loan_id: raise ValidationError` 强制要求，支持 loan_id 为空的纯报销；纯报销走 §3 两段式（2241.06 → 1002）。
4. **plan_id 可空**：借款单/报账单的 `plan_id` 由 required 改为可空（员工备用金、员工费用报销不挂团）。
5. **expense_type 扩展**：新增 `visa 签证费`（deductible=True）、保留 `guide 导服费`；员工费用类型补"差旅/办公/招待/其他"映射到 6601/6602 明细。
6. **deductible 规则**：`_onchange_expense_type` 改为复合判断（性质 + 挂团成本 + 发票号）。
7. **内控扩展**：报账单新增 `business_approver_id`（业务审批人），与 `auditor_id`（财务审核）、付款人三方校验分离；分级限额字段（`loan_limit` 按职级）。
8. **company 隔离**：借款/报账单 `company_id` 强制继承 `employee_id.company_id`，跨公司校验。
