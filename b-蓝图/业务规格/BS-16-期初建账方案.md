## 三、期初余额确定方法（推导 + 假设）

### 3.1 核心原则（唯一可推导的缺口）

> **经营类往来科目（应收/应付/预收/税）期初为 0** —— 其发生额已 100% 由迁移的 8.69 万订单凭证覆盖，不存在期初缺口。
> **唯资金科目（银行）期初非 0** —— 迁移凭证只覆盖「订单现金流」（收客户团款、付供应商款），缺少「期初存量资金」与「非订单现金流」（注资、借款、其他收支），故透支。

### 3.2 期初银行存款（推导，公式化）

```
期初银行存款 = |当前透支额| + 目标期末银行余额
             = 61,725,862.34 + 9,228,332.70
             = 70,954,195.04 元
```

- **当前透支额 61,725,862.34**：精确值（1002 净额绝对值，live DB 实测）。
- **目标期末银行余额 9,228,332.70**：取源数据 `accounts.csv` 的 `BalanceMoney` 合计（易途 72 个银行/第三方账户余额快照）。⚠️ **此为业务输入**，需公司财务确认实际期末银行余额；如确认值不同，代入公式重算期初即可，公式不变。

### 3.3 期初权益（平衡数 + 业务输入）

```
期初权益 = 期初资产 − 期初负债 = 70,954,195.04（因其他科目期初均为 0）
期初权益 = 实收资本(4001) + 未分配利润(4104)
```

- **实收资本 4001**：公司注册资本/实缴资本，**源数据无此字段（companies.csv 无注册资本）**，须公司财务提供。默认建议 **0 或按实际注册资本填入**。
- **未分配利润 4104**：**平衡数** = 70,954,195.04 − 实收资本。

### 3.4 期初建账日期

- **推荐 2026-01-01**（建账基准日，与 2026 上线一致）。
- ⚠️ 说明：迁移凭证日期跨 2019-09-30 ~ 2027-01-04（历史数据一次性导入），三表验证以「**全量凭证**」为口径，不按自然年切分。若需按自然年出报表，应将 2019-2025 凭证并入期初余额（"完整建账"变体），本文不展开，列为后续项。

### 5.2 利润表（不受期初影响）

### 5.3 现金流量表（期初余额 = 期初现金）

- 期初现金及现金等价物 = **70,954,195.04**（期初建账银行余额）。

### 6.2 SQL 验证脚本（dev-odoo 直接执行）

```sql
-- 1. 期初建账后银行余额应为正
SELECT ROUND(SUM(l.debit)-SUM(l.credit),2) AS bank_balance
FROM account_move_line l
JOIN account_move m ON m.id=l.move_id
JOIN account_account a ON a.id=l.account_id
WHERE m.state='posted' AND a.code_store->>'1'='1002';
-- 期望：+9,228,332.70

-- 2. 全库借贷平衡
SELECT ROUND(SUM(debit),2) total_dr, ROUND(SUM(credit),2) total_cr,
       ROUND(SUM(debit)-SUM(credit),2) diff
FROM account_move_line l JOIN account_move m ON m.id=l.move_id
WHERE m.state='posted';
-- 期望：diff = 0.00

-- 3. 权益 = 资产 - 负债
-- 资产 = 1002+1122+1221+1123+1012（借差）；负债 = 2202+2203+2221+2241+2211（贷差）
-- 权益 = 4001+4104+本年损益（6001贷差−6401借差）
-- 期望：资产 − 负债 − 权益 = 0

-- 4. 损益科目未被期初凭证触碰
SELECT COUNT(*) FROM account_move_line l
JOIN account_move m ON m.id=l.move_id
WHERE m.ref LIKE '%期初%' AND l.account_id IN (
  SELECT id FROM account_account WHERE account_type IN ('income','income_other','expense','expense_direct_cost'));
-- 期望：0
```
