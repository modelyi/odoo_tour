## 一、文档定位与范围

BS-10 已把科目、凭证、analytic、收入确认（无税）、佣金、对账全部落到 Odoo 原生 `account`，但**销项税（差额征税）留白为 Phase 3**（BS-10 §7.2.1 注释、`tour_plan.action_recognize_revenue()` 的无税实现、`account_account.tour_vat_deductible` 字段均已预留）。

本文定义 Phase 3 的**差额征税销项税**落账方案，是 BS-10 的"税层"细化，覆盖：

1. 差额征税原理与法规依据（财税〔2016〕36号 附件2）；
2. 纳税人身份（一般/小规模）与税率/征收率；

7. 纳税人身份配置（`res.config.settings` / `res.company`）；

> **权威口径声明**：本文与 BS-10 存在重叠处（§7.2 收入确认、§7.3 成本、AC-14），以本文为准——BS-10 §7.2.1 的"差额征税走 fiscal.position 归集到 2221.03"注释**不准确**（差额征税不是单纯税率映射，需专门抵减分录），本文 §七 给出正确分录。

## 二、差额征税原理（财税〔2016〕36号）

### 2.1 法规依据

> **[财税2016-36号]《关于全面推开营业税改征增值税试点的通知》附件2《营业税改征增值税试点有关事项的规定》第一条第（三）项第8点**

试点纳税人提供**旅游服务**，可以选择以取得的**全部价款和价外费用**，扣除向旅游服务购买方收取并支付给其他单位或个人的下列费用后的**余额为销售额**：

1. 住宿费
2. 餐饮费
3. 交通费
4. 签证费
5. 门票费
6. 支付给其他接团旅游企业的旅游费用（地接费）

### 2.2 可扣除 / 不可扣除项目（与 BASELINE §2.2 一致）

| 项目 | 差额扣除 | 对应成本科目 | 凭证类型 |
|------|:-------:|-------------|---------|
| 住宿费 | ✅ 可扣除 | 6401.02 / 2202.02 | 住宿发票 |
| 餐饮费 | ✅ 可扣除 | 6401.03 / 2202.03 | 餐饮发票 |
| 交通费 | ✅ 可扣除 | 6401.04 / 2202.04 | 运输客票/专票 |
| 门票费 | ✅ 可扣除 | 6401.05 / 2202.05 | 景区门票（定额/电子票） |
| 签证费 | ✅ 可扣除 | 6401.06 / 2202.06 | 签证机构收费凭证 |
| 地接费 | ✅ 可扣除 | 6401.01 / 2202.01 | 地接社旅游服务发票 |
| 导服费 | ❌ 不可扣除 | 6401.07 / 2202.07 | 劳务发票（进项可扣时另论） |
| 保险费 | ❌ 不可扣除 | 6401.08 / 2202.08 | 保险发票 |
| 自费项目 | ❌ 不可扣除 | 6401.09 / 2202.09 | 自费项目发票 |
| 购物成本 | ❌ 不可扣除 | 6401.10 / 2202.10 | 购物进货发票 |

> **[财税2016-36号]** 可扣除项目对应的扣税凭证，其**进项税额不得从销项税额中抵扣**——差额征税是"扣销售额"而非"抵进项"，两者不得叠加。

### 2.3 选择适用与 36 个月锁定

> **[财税2016-36号]** 差额征税是**选择适用**：纳税人可选择差额征税，也可选择全额计税（一般纳税人取得专票抵扣进项）。**一经选择，36 个月内不得变更。**

**TMS 落地**：纳税人身份/计税方式作为公司级配置（§十），配置变更需记录并提示"36 个月锁定"约束（软提示，不强制技术锁定，由财务主管确认后变更）。

### 2.4 凭证合规要求（发票归集）

差额扣除必须取得**合法有效凭证**：

> **[财税2016-36号附件2]** 支付给境内单位或个人的款项，以**发票**为合法有效凭证；支付给境外单位或个人的款项，以该单位或个人的**签收单据**为合法有效凭证。

- 无票部分（`un_invoice_money > 0`）**不得参与差额扣除**（BS-10 §4.6 / AC-14）。
- 差额征税模式下，向旅游购买方收取并支付的可扣除项目，**不得开具增值税专用发票**（只能开普票）——购买方（游客）是最终消费者，不可抵扣。

## 三、纳税人身份与税率

### 3.1 身份判定

| 身份 | 判定标准 | 计税方式 |
|------|---------|---------|
| 一般纳税人 | 年应征增值税销售额 > 500 万元（或主动登记） | 税率 6%，差额计税（销项税额抵减） |
| 小规模纳税人 | 年销售额 ≤ 500 万元 | 征收率 3%（现行减按 1%），差额计税 |

### 3.2 税率 / 征收率表

| 身份 | 适用 | 名义税率 | 现行优惠 | 配置字段（§十） |
|------|------|:-------:|---------|----------------|
| 一般纳税人 | 旅游服务（生活服务） | 6% | 无 | `tour_vat_rate` = 6.0 |
| 小规模纳税人 | 旅游服务 | 3% | 减按 1%（至 2027-12-31） | `tour_vat_levy_rate` = 3.0（优惠期调 1.0） |

> **[财税2016-36号]** 旅游服务属"生活服务—旅游娱乐服务"，一般纳税人税率 6%。
> **[财政部 税务总局公告2023年第19号]** 小规模纳税人适用 3% 征收率的应税收入减按 1% 征收，执行至 2027-12-31（阶段性优惠，须可配置）。

### 3.3 ⚠️ 待业务确认事项

**海螺旅行社的纳税人身份尚未确认，是影响税率与分录的硬前置输入。** finance-ba 不臆断，交付前须由项目组/财务确认：

| 确认项 | 选项 | 影响 |
|--------|------|------|
| 纳税人身份 | 一般纳税人 / 小规模纳税人 | 税率 6% vs 征收率 3%(1%) |
| 是否选择差额征税 | 是 / 否（全额+进项抵扣） | 是否启用抵减分录 |
| 小规模是否适用 1% 优惠 | 是 / 否 | 征收率字段取值 |

> 默认建议（供参考，待确认）：旅行社年度营业额通常超 500 万，大概率**一般纳税人 + 差额征税**。若为小规模，则走 §4.2 / §7.1.2 口径。系统按 §十 配置项在**运行时动态取税率**，身份切换不改代码、只改配置。

## 四、计税规则与公式

### 4.1 符号约定

| 符号 | 含义 | TMS 字段 |
|------|------|---------|
| `G` | 含税全部价款（客户实付/应收） | `in_com_quo_sum` / `sum_pay_normal`（总额法） |
| `D` | 可扣除项目**含税**合计（6 类，有合规凭证） | Σ 成本借方 where `tour_vat_deductible=True` 且有票 |
| `N` | 不可扣除项目含税合计 | Σ 成本借方 where `tour_vat_deductible=False` |
| `r` | 本企业税率/征收率（一般 6%，小规模 3% 或 1%） | §十 配置 |

### 4.2 一般纳税人（税率 6%，财会〔2016〕22号口径）

```
差额销售额（含税）  = G - D
销售额（不含税）    = (G - D) ÷ (1 + r)
销项税额           = 销售额 × r = (G - D) ÷ (1 + r) × r

等价分解（用于分录）：
  全额销项税额     = G ÷ (1 + r) × r
  销项税额抵减     = D ÷ (1 + r) × r
  净销项税额       = 全额销项税额 - 销项税额抵减
```

> **[财会2016-22号]** 抵减额按**本企业税率** `r` 计算，用**可扣除项目的含税金额** `D`，**不需要**分项换算供应商税率（住宿 6%/交通 9%/门票免税等一律按含税金额统一扣除）。

### 4.3 小规模纳税人（征收率 3% 或 1%）

```
销售额（不含税） = (G - D) ÷ (1 + r)
应交增值税       = 销售额 × r
```

小规模与一般纳税人的**抵减分录对称**（财会22号同样规定小规模抵减借记"应交税费——应交增值税"、贷记"主营业务成本"），差异仅在：税率 `r`（3%/1%）与税额科目（单一科目 2221.07，不分专栏）。

### 4.4 计算示例

#### 示例 A：一般纳税人 6%，总额法（组团 DTO）

- 收客户含税团款 `G` = 106,000 元
- 可扣除项目含税 `D` = 63,600 元（住宿/餐/交通/门票/地接/签证，均有票）
- 不可扣除项目含税 `N` = 10,600 元（导服/保险）

```
差额销售额（含税）= 106,000 - 63,600 = 42,400
销售额（不含税）  = 42,400 ÷ 1.06 = 40,000
销项税额         = 40,000 × 6% = 2,400
全额销项税额     = 106,000 ÷ 1.06 × 6% = 6,000
销项税额抵减     = 63,600 ÷ 1.06 × 6% = 3,600
```

分录（§7.1.1 + §7.2）见下，最终：销项净额 6,000 − 3,600 = **2,400** ✓，成本净额 63,600 − 3,600 = 60,000（不含税）。

#### 示例 B：小规模纳税人 3%，总额法

- `G` = 103,000，`D` = 51,500

```
差额销售额 = 103,000 - 51,500 = 51,500
销售额     = 51,500 ÷ 1.03 = 50,000
应交增值税 = 50,000 × 3% = 1,500
全额税额   = 103,000 ÷ 1.03 × 3% = 3,000
抵减额     = 51,500 ÷ 1.03 × 3% = 1,500
```

净应交 = 3,000 − 1,500 = **1,500** ✓。

#### 示例 C：净额法（地接 DT，差价计税，不差额扣除）

- 收组团社全额团款 106,000（代收代付，不进损益）
- 转付地接社 100,000；差价 = 6,000（含税）

```
差价销售额（不含税）= 6,000 ÷ 1.06 = 5,660.38
销项税额           = 5,660.38 × 6% = 339.62
```

净额法下税基 = 差价本身，**无差额扣除环节**（§九）。

## 五、金额口径约定（含税）

> **[口径决策 D1]** TMS 业务金额字段一律为**含税口径**（客户实付 / 供应商实收），这是旅行社报价的天然口径。

| 字段 | 口径 | 说明 |
|------|------|------|
| `in_com_quo_sum` 收入报价 | 含税 | 客户应付的全额团款 |
| `sum_pay_normal` 已收款 | 含税 | 客户实付 |
| `in_sum` 收入合计 / `out_sum` 成本合计 | 含税 | 报价/成本汇总 |
| `sum_un_pay` / `sum_money_return` | 含税 | 应收/退款 |

**Phase 3 除税规则**：所有"确认收入/确认成本"涉及税额的计算，先按 `含税 ÷ (1+r)` 价税分离，再分别入"收入（不含税）"与"应交增值税"科目。Phase 2 的 `action_recognize_revenue()` 目前把 `amount` 全额贷入主营收入（无税），Phase 3 须改造为拆税（§七）。

| 2 | 贷 | 6001.02/03 主营收入—地接/代订 | `差价 ÷ (1+r)` | — | [团] | [CAS 14-代理人] |
| 3 | 贷 | 2221.01 应交增值税(销项) | `差价 ÷ (1+r) × r` | — | — | [财税2016-36号] |

**示例 C 数字**：借 2241.01 = 6,000；贷 6001.02 = 5,660.38；贷 2221.01 = 339.62 ✓

> 小规模净额法同理：税额科目换 2221.07，税率 `r` 换 3%/1%。

## 八、与 `tour_vat_deductible` 字段联动

`account_account.tour_vat_deductible`（已实现，科目级布尔）是差额扣除的**科目判定开关**。Phase 3 联动机制：

### 8.1 判定与归集链路

```
成本凭证行.account_id.tour_vat_deductible == True
        │
        ▼
  属「可扣除项目」
        │
        ▼ 校验发票：该团 un_invoice_money 覆盖额度（无票不扣）
        │
        ▼
  抵减额 = 可扣除含税额 ÷ (1+r) × r
        │
        ▼
  生成抵减凭证：借 2221.03/2221.07 / 贷 6401.0N
        │
        ▼
  归集到 tour.plan.account.cost_deductible / cost_non_deductible
```

### 8.2 台账字段填充（Phase 3 需补 compute）

`tour.plan.account` 现有 `cost_deductible` / `cost_non_deductible` 为**普通 Float 字段（无 compute）**，Phase 3 须补充派生逻辑：

```
cost_deductible     = Σ analytic.line 成本借方 where 科目.tour_vat_deductible=True（且有票）
cost_non_deductible = Σ analytic.line 成本借方 where 科目.tour_vat_deductible=False
```

> 建议改为 `compute`，依赖 `analytic_account_id` 的分析行（记账真相），与 `income_total`/`cost_total` 的 `_compute_from_analytic` 同源（BS-10 §6.2 / TDS §4.3）。

### 8.3 发票缺口校验（无票不扣）

> **[财税2016-36号][合规风险-差额征税扣除不合规 🔴]** 可扣除项目必须取得合法有效凭证方可扣除。

- 抵减基数 `D' = D − 无票可扣除额`；无票部分（`un_invoice_money` 中对应可扣除科目的额度）**不参与抵减**。
- 简化实现（Phase 3）：以团的 `un_invoice_money` 作为无票口径，`D' = max(0, D − un_invoice_money)`；精细到科目级的发票归集留 BS-05 §2.1 / BS-10 §8.5 的发票管理闭环。

## 九、净额法 vs 总额法对差额征税的影响

> **核心合规点**：CAS 14 的"总额法/净额法"与财税36号的"差额征税"是**两套独立规则**，不可混用。

| 维度 | 总额法（主要责任人） | 净额法（代理人） |
|------|--------------------|-----------------|
| 适用 biz_mode | DTO(21)、DSO(31) | DT(1,2)、DSK(12)、DSS(13)、DSN(14,15)、DD(41) |
| 会计收入确认 | 全额确认收入 | 仅差价确认收入 |
| 增值税税基 | 全额 − 可扣除项目（差额征税） | 差价本身（代收代付不进销售额） |
| 是否差额扣除 | **是**（§7.2.2 抵减分录） | **否**（无抵减环节） |
| 税会差异 | 收入=全额不含税，成本=不含税（抵减后），销项=差额×r | 收入=差价不含税，销项=差价×r |

**关键结论**：

1. **差额征税只适用于总额法**。净额法下代收代付已走 2241.01 不经损益，税基天然是差价，再叠加差额扣除会**重复扣除**。
2. 若净额法团中成本混有不可扣除项目（导服/保险），其税基 = 差价（已含不可扣除项目的"贡献"），与总额法"差额 = 差价 + 不可扣除项目"口径不同——这是 CAS 14 收入口径决定的，非税计算错误。
3. 总额法 + 差额征税的**最终销项净额 = (全额 − 可扣除) ÷ (1+r) × r**，与"总收入按差额确认"的直觉一致，但分录上收入仍按**全额**确认（CAS 14 主要责任人），差额通过 2221.03 抵减体现。

### 10.3 运行时取税率的公共方法（记账方法调用）

```python
def _tour_vat_params(self):
    """返回 (taxpayer_type, rate, enabled)。rate = 一般6% / 小规模3%(1%)。"""
    co = self.env.company
    rate = co.tour_vat_rate if co.tour_taxpayer_type == 'general' else co.tour_vat_levy_rate
    return co.tour_taxpayer_type, rate, co.tour_vat_deduction_enabled

def _tour_vat_account(self):
    """销项税科目：一般→2221.01，小规模→2221.07。"""
    return (self.ACCOUNT_TAX_OUTPUT if self.env.company.tour_taxpayer_type == 'general'
            else self.ACCOUNT_TAX_SIMPLE)
```
