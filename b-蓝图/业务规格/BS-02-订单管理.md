# BS-02-订单管理

> 编写人：tour-ba
> 版本：v1.0
> 日期：2026-09-12

## 1. 业务背景

订单是旅行社业务的核心载体，承载「客户报名 → 确认并团 → 计调执行 → 财务结算」全流程。当前海螺旅行社在易途系统中累计产生 **86,925 条团队订单**（137 字段）和 **86,753 条订单报名**（77 字段），覆盖 12 种业务模式（团队输单、散客并团、自由行、代订等）。

业务痛点：
- 订单字段过多（137 个），实际使用率不足 40%，大量冗余
- 并团逻辑复杂（散客并团、关键字并团、自由行多订单），操作不直观
- 订单状态流转不清晰，缺少可视化状态机
- 多类型客人（成人/儿童/老人/婴儿/学生/导游）混合计价规则不明确
- 订单变更（单团变更、退改）缺少完整日志

## 3. 业务流程

### 3.1 散客订单流程（先报后并）

```
客户咨询 → 选择发团计划
    ↓
创建报名单（填写客人信息、人数、房型需求）
    ↓
系统自动计价（按客人类型 × 单价）
    ↓
确认报名（生成 RegCode）
    ↓
并团操作（将报名单关联到发团计划）
    ↓
订单审核（大额/特殊折扣需审批）
    ↓
收款确认（财务认领收款到订单）
    ↓
计调操作（派车、派导、订房、订餐）
    ↓
出团执行
    ↓
回团结算（导游报账、购物佣金）
    ↓
订单归档
```

### 3.2 团队订单流程（先计划后报名）

```
客户咨询 → 定制线路需求
    ↓
创建团队订单（选择线路、设置出发日期、人数）
    ↓
系统自动计价（可按团队协议价）
    ↓
订单审核
    ↓
收款确认
    ↓
计调操作（资源采购、派车派导）
    ↓
出团执行
    ↓
回团结算
    ↓
订单归档
```

### 3.3 订单状态流转

```
草稿（Draft）
    ↓ 提交
待确认（Pending）
    ↓ 确认
已确认（Confirmed）
    ↓ 计调操作
计调中（Operating）
    ↓ 出团
出行中（In Progress）
    ↓ 回团
已完成（Completed）
    ↓ 归档
已归档（Archived）

特殊状态：
- 已取消（Cancelled）：任意阶段可取消，需记录原因
- 已退款（Refunded）：退款完成后
```

### 3.4 并团逻辑

**散客并团（DSN 模式）**：
1. 多个散客报名单（RegID）关联到同一发团计划（PlanID）
2. 系统自动合并客人名单
3. 房型需求按报名单独立记录，计调统一安排
4. 并团后生成统一团号（PlanCode）

**关键字并团（模式 18）**：
1. 行程以"选择线路"形式添加
2. 按关键字（线路名称+日期）自动匹配合并
3. 适用于碎片化行程拼接

**自由行（模式 51/52）**：
1. 一组客人多订单（51）：同一客人预订多个独立服务
2. 多组客人多订单（52）：多组客人共享部分服务
3. 订单间通过 MainRegID 关联

## 4. 功能需求

### 4.1 订单创建

| 功能 | 说明 | 业务规则 |
|------|------|----------|
| 报名单创建 | 散客模式（DSN/DSS） | 必填：客人联系人、发团计划、人数（至少 1 人） |
| 团队订单创建 | 团队模式（DT/DTO） | 必填：客户档案、线路、出发日期、人数 |
| 多类型客人 | AdultNum、ChildNum、OldManNum、BabyNum、StudentNum、GuideNum | 总人数 = 各类型之和；GuestCount 为有效客人数（不含婴儿） |
| 房型需求 | HotelRoom_Single/Standard/Triangle/Accompany/Additional | 标准间、单间、三人间、陪同房、加床房 |
| 交通信息 | ReceivePlace/Traffic（接站）、LeftPlace/Traffic（送站） | 可选，接送业务必填 |
| 订单来源 | FromType：NB(内部)、MS(门市)、TH(同行)、LZ(集团流转) | 影响计价规则（同行价 vs 门市价） |
| 业务模式 | BizMode：12 种模式 | 决定订单流程和视图 |
| 订单类型 | RegOrderType：DT/DS/ZT/ZS/DD/JS/BG | DT(团队)、DS(散客)、ZT(组团团队)、ZS(组团散客)、DD(代订)、JS(接送)、BG(变更) |

### 4.2 订单计价

| 功能 | 说明 | 业务规则 |
|------|------|----------|
| 自动计价 | 按客人类型 × 单价自动计算 | outPrice_QuoSum（报价总额）= Σ(人数 × 单价) |
| 同行价 | TH 来源订单使用同行价 | 同行价 ≤ 门市价 |
| 预报价 | PrePrice_QuoSum | 订单创建时锁定，后续变更不影响 |
| 代收代付 | SumMoney_Delegate、SumPay_Delegate | 代收项目（门票、保险等）独立核算 |
| 返款 | SumMoney_Return、SumPay_Return | 同行返款，按协议计算 |
| 利润计算 | Profit = InSum - OutSum | InSum（收入）、OutSum（成本） |
| 购物佣金 | InSum_NoShop、OutSum_NoShop | 剔除购物佣金后的纯利润 |

### 4.3 并团操作

| 功能 | 说明 | 业务规则 |
|------|------|----------|
| 散客并团 | 将多个报名单关联到同一发团计划 | 同一发团计划的报名单可批量并团 |
| 主报名单 | MainRegID、MainRegCode | 并团后指定一个主报名单，其他为子报名单 |
| 团号生成 | PlanCode | 并团后自动生成团号（规则可配置） |
| 名单合并 | 系统自动合并所有子报名单的客人名单 | 计调可查看完整名单 |
| 关键字并团 | 按线路名称+日期自动匹配 | 适用于碎片化行程 |

### 4.4 订单变更

| 功能 | 说明 | 业务规则 |
|------|------|----------|
| 增加客人 | 修改 AdultNum/ChildNum 等 | 触发重新计价，生成变更记录 |
| 减少客人 | 减少人数 | 触发重新计价，已收款需退款审批 |
| 变更房型 | 修改 HotelRoom_* 字段 | 记录变更日志 |
| 变更行程 | 修改发团计划 | 需计调确认，影响已安排资源 |
| 单团变更 | PlanChangeList | 独立变更记录表，关联原订单 |
| 变更审批 | 大额变更需审批 | 审批规则可配置 |

### 4.5 订单审核

| 功能 | 说明 | 业务规则 |
|------|------|----------|
| 订单审核 | AuditChk、AuditChk0 | 两级审核（初审、复审） |
| 审核条件 | 大额订单、特殊折扣、同行订单 | 条件可配置 |
| 审核记录 | AuditChk_UserName、AuditChk_Date | 记录审核人和时间 |
| 驳回处理 | 驳回后订单回到草稿状态 | 可重新编辑提交 |

### 4.6 订单查询

| 功能 | 说明 | 业务规则 |
|------|------|----------|
| 多条件检索 | 按团号、客户、线路、日期、状态 | 支持组合查询 |
| 高级筛选 | 按业务模式、订单类型、来源、部门 | 支持保存常用筛选条件 |
| 订单导出 | 导出 Excel | 支持自定义导出字段 |
| 订单打印 | 打印行程单、合同 | 模板可配置 |

### 4.7 核心业务规则汇总

1. **人数校验**：总人数 = AdultNum + ChildNum + OldManNum + BabyNum + StudentNum + GuideNum；GuestCount = 总人数 - BabyNum（婴儿不计入有效客人）
2. **房型校验**：标准间数 × 2 + 单间数 × 1 + 三人间 × 3 + 加床房 × 1 ≥ 成人数 + 儿童数（儿童占床）
3. **日期校验**：EndDate ≥ BeginDate；BeginDate ≥ 当前日期（新建订单）
4. **并团约束**：同一发团计划的报名单才能并团；并团后不可拆分
5. **变更约束**：已出团订单不可变更；已归档订单不可变更
6. **退款约束**：退款金额 ≤ 已收款金额；退款需走审批流程
7. **权限隔离**：用户只能查看本公司/部门订单（OpCmpID/OpDptID）
