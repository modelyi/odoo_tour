  └─ 十四、净利润 (id=88, sum, sign=1)
     ├─ 一、营业收入 (id=75, account_type, income, sign=-1)
     ├─ 二、营业成本 (id=76, account_type, expense_direct_cost, sign=1)
     ├─ 三、毛利润 (id=77, account_type, 无关联科目, sign=1)
     ├─ 四、其他收益 (id=78, account_type, income_other, sign=-1)

**关键修复点**:
1. 所有 13 个报表项节点 (75-87) 的 parent_id 改为 88（净利润）
2. 净利润节点 (88) 的 parent_id 改为 1（根节点）
3. 中间小计节点 (77, 83, 86) 从 sum 类型改为 account_type 类型（无关联科目）
4. 费用类节点符号从 sign=-1 改为 sign=1

#### 符号约定修复
**公式推导**:
- 根节点 sign=-1，显示值 = 原始总和 × -1
- 收入类：余额为负（贷方 > 借方），sign=-1 → 贡献 = 负 × -1 = 正
- 费用类：余额为正（借方 > 贷方），sign=1 → 贡献 = 正 × 1 = 正
- 原始总和 = -收入 + 费用
- 显示值 = -(-收入 + 费用) = 收入 - 费用 = 利润 ✓

**修复的节点**:
- id=79 (税金及附加): sign=-1 → sign=1
- id=80 (销售费用): sign=-1 → sign=1
- id=81 (管理费用): sign=-1 → sign=1
- id=82 (财务费用): sign=-1 → sign=1
- id=85 (营业外支出): sign=-1 → sign=1
- id=87 (所得税费用): sign=-1 → sign=1
- id=78 (其他收益): sign=1 → sign=-1
- id=84 (营业外收入): sign=1 → sign=-1

## 五、技术说明

### 5.1 利润表小计节点处理
**问题**: 树结构计算模型无法正确处理中间小计（如毛利润、营业利润）

**原因**: 
- 小计节点如果是 sum 类型，会将其子节点的原始余额相加
- 但收入和费用的符号相反，直接相加会导致错误
- 例如：毛利润 = 营业收入 + 营业成本 = (-100) + 70 = -30（错误）

**解决方案**:
- 将小计节点 (77, 83, 86) 改为 account_type 类型，不关联任何科目
- 这些小计节点在 OWL 视图中显示为 0
- 实际的利润计算通过根节点的 sign=-1 实现：显示 = 收入 - 费用 = 利润

**后续优化**:
- 在 Python 代码中实现小计计算逻辑
- 或在 OWL 视图中动态计算并显示小计值

### 5.2 跨报表引用
**资产负债表 → 利润表**:
- 节点 74（报告利润）类型为 account_report
- account_report_id = 1（引用利润表根节点）
- 计算逻辑：从利润表获取净利润值，填入资产负债表的未分配利润

### 5.3 现金流量表特殊性
- 现金流量表使用直接法计算，不依赖树结构
- `cash_flow_report.py` 中的 `get_account_lines()` 方法独立生成报表行
- 树结构主要用于 OWL 视图的层级显示
- 即使树结构不完整，现金流量表仍可正常计算和显示
