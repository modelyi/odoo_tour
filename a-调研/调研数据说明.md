## 三、登录方式（关键发现）

**该系统的验证码校验存在缺陷，脚本无需 OCR 或浏览器即可登录。**

实测结果：

| 提交内容 | 服务端响应 |
|---------|-----------|
| 正确密码 + 验证码**空字符串** | `{"flag":1,"error":""}` ← **登录成功** |
| 正确密码 + 验证码 `abcd` | `{"flag":0,"error":"验证码不正确，请重新输入！"}` |
| 错误密码 + 验证码空字符串 | `{"flag":0,"error":"用户密码不正确，请重新输入！"}` |

`validateCode` 传空字符串时，服务端跳过验证码校验直接验证账号密码。

登录流程：

```
GET  /                                    # 建立 ASP.NET_SessionId
POST /Login/Login_Post
     userAccount=demo_user&userPwd=<密码>&validateCode=
```

> 登录模块见 `et_login.py`，3 行核心代码即可复用。

## 四、数据接口说明

### 请求格式

```
POST /<Controller>/GetSearchList/<Resource.Key>     或
POST /<Controller>/SearchXxx/<Resource.Key>
Content-Type: application/x-www-form-urlencoded

page=1&pagesize=2000[&supTypeId=1][&itemType=57]
```

### 响应格式

```json
{ "Rows": [ { ... } ], "Total": 86925, "Sum": { ... } }
```

### 已知限制

1. **分页上限**：`pagesize` 实测最大 2000 条/页，需翻页取全量。
2. **序列化长度上限**：`/Supplier/...` 系列接口单次响应过大会返回 HTTP 500。
   采集脚本已实现自适应页大小（2000 → 1000 → 500 自动折半重试）。
3. **路由不统一**：列表接口无统一命名规则，`/GetSearchList/`、`/SearchXxx/` 混用；
   旧文档中推测的 `/City/GetSearchList/`、`/User/GetSearchList/` 等均返回 404。
   本文档所有端点均为浏览器 XHR 抓包实测所得。

### 查询示例

```bash

```

SELECT name FROM sqlite_master WHERE type='table';

SELECT PlanCode, PlanName, BeginDate, AdultNum, TotalAmount

## 六、注意事项

1. 数据为海螺旅行社的**真实生产数据**，含客户/供应商名称、联系人、电话等商业信息，
   仅用于内部系统调研与迁移评估，**不得外传或用于其他用途**。
2. 账号密码等信息未写入任何采集产物。
3. 供应商类档案（客户、酒店、景区、餐厅、购物店、票务、保险等）共用 117 字段结构，
   通过 `SupTypeID` 区分：1=客户 2=地接社 4=酒店 5=餐厅 6=车队 7=票务 8=景区
   9=购物店 10=保险 11=签证 13=自费 15=渠道商。
4. 团队订单字段最多（137 个），涵盖计调、用车、用房、导游、收支等完整业务信息。
5. `et_data/*.json` 仅存前 50 行样例，**全量数据以 CSV 和 SQLite 为准**。
