## 五、问题清单（分级）

### P0（阻断/财务正确性）

**P0-1　计调环节整体缺失，主线断链**
- 现象：`project`/`tour_operation`/`tour_tutor` 于 `2026-09-14 11:29:18` 被卸载；`project_project`/`project_task` 表不存在；`tour_plan.project_id` 列不存在。
- 影响：BS-03 的 5 类资源预订（派导/派车/订房/订餐/门票）、冲突检测、出团前置校验、以及「团=project=analytic 三者同源」全部无法执行/验收；`action_operate` 仅推进状态不产生任何计调对象。
- 证据：`ir_module_module.write_date`；`pg_tables` 0 行；`\d tour_plan` 无 `project_id`；场景1 步骤3、场景4.4、场景5 步骤2.4 实测。
- 建议：devops/dev 确认是有意下线还是并发开发中间态；若为后者，重装后再跑本报告场景1 步骤3 即可补齐。

**P0-2　收入确认幂等键失效 → 重复确认收入（敞口 33,945 团 / ¥88,189,585.76）**
- 现象：`income_move_id` 为空但账上已确认收入的团，再次执行收入确认会**重复入账**。
- 实测：团 88791 收入翻倍 7707.55 → 15,415.10（`6001.01` 分析行 ×2：`MISC/2026/09/74972`＋`INV/2026/10275`）。

- 连带：应收重复挂账（88791 收款 8170 已入 2203.01、收入已结转，`1122.01` 仍净挂 8170）。
- 建议：以「账上是否已有 6001.* 分析行」而非单一 `income_move_id` 作幂等判据，并做一次存量回填；执行 `run_otc_posting.py` 类批量脚本前必须先修。

### P1（功能缺失/一致性破坏）

**P1-1　并团（tour.merge）无业务逻辑**
- `tour.merge` 仅有字段，无任何 `action_*` 业务方法；创建记录后 `first_plan_id`/`plan_id` 不变、团金额不汇总、人数不累加、快照为空（场景3 五项 FAIL）。
- 影响：并团完全人工，且无审计快照可回退；BS-02 并团设计未落地。
- 备注：**核算侧不分裂（团↔analytic 1:1）本身成立**，不构成财务风险。

**P1-2　差额征税抵减在真实数据下不可达**
- 双重原因：① 成本账单统一落 `6401`（`tour_vat_deductible=False`），而可扣除科目是 `6401.01–6401.06`；② `_vat_deductible_base = max(0, 可扣除 − un_invoice_money)`，而存量团 `un_invoice_money` = 团全额 → 基数恒为 0。
- 实测：88791 现状 可扣除 0 / 缺口 8170 → 拒绝生成；补录 600 元 `6401.02` 并置缺口 0 后机制正常（借 2221.03 33.96 / 贷 6401.02 33.96，幂等成立）。
- 影响：`vat_deduct_move_id` 全库仅 1 条（本轮测试产生），差额征税申报口径实际未跑通。

**P1-3　承载团（同线路同班期）复用无状态校验**
- 场景2.17：已 `completed` 且已确认收入 2250 的团被再次复用承接电商报名，团金额被改写为 2700，已过账收入凭证未同步 → 团金额 ≠ 已确认收入（差 450）。
- 建议：`_get_or_create_plan` 增加状态校验（completed/archived 时新建团或触发调整）。

**P1-4　线上报名路径不产生成本 → 单团毛利虚高**
- `create_online_reg`/电商桥接只写报价，`out_sum=0`；收入确认后毛利=全额收入（场景1 若不计人工录入的 1500 成本，毛利=2122.64 即 100%）。
- 影响：官网/电商成团的单团核算在成本录入前严重失真。

**P1-5　收款无法核销存量团应收**
- `tour_invoice_plan_rel` 0 条、`tour_payment_claim_line` 32 条 → 收款一律贷 `2203.01` 预收；存量团的 `1122.01` 应收永不核销，全库未核销净额 **57,297,249.88**。
- 实测：88791 收款 8170 已入账、收入已确认，仍挂应收净 8170。
