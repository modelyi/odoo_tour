## 5. 发现

### 5.1 库级缺陷（重要）：登记付款在存量日记账上产生"无凭证的已付款"

- 现象：用存量日记账对供应商账单「登记付款」，payment 立即 state=paid，但 `move_id` 为空、无分录、账单余额不清偿。
- 根因：全库 **1086 条 `account.payment.method.line` 的 `payment_account_id` 均为空**（tms19 导入的日记账从未配置付款方法账户）。Odoo 20 中 `outstanding_account_id` 取自 `payment_method_line_id.payment_account_id`，为空 → `_generate_journal_entry` 的 `need_move` 过滤（`not p.move_id and p.outstanding_account_id`）排除该付款 → 永不生成分录。批3 验收为只读，未触及此路径，故未被发现。
- 本批处置：仿真新建专用日记账「仿真|银行存款」(SIMBANK) 并补全其付款方法行账户后走通付款闭环；**未**静默全库修复（修复属数据变更，需单独方案）。
- 产品影响与建议：这是真实用户首次付款即会踩中的路径缺陷。建议批4 排入：① 日记账表单保存时对缺失 payment_account_id 的付款方法行自动补默认账户或强校验提示；② 数据修复脚本为 1086 行补账户；③ 付款向导侧兜底：创建付款时校验 outstanding_account_id 非空。

### 5.2 单团损益视图无搜索视图（已知，批4 已规划）

`ta.team.pnl` 未定义 search view，搜索框全文搜索落到无 `_rec_name` 的 SQL 视图 name_search → 返回无关/空结果。UI 取证以「首屏滚动定位」绕过（date_start desc 下 2026-10-03 以后仅 63 行）。批4 已规划 `_rec_names_search=['code','route_name']`。

### 5.3 应收账龄全文搜索返回空

同上：SQL 视图 + 无 `_rec_name`，输入单号回车 → 空列表（非报错）。取证以「账龄锚点列降序」绕过。建议与 5.2 一并修复（`_rec_names_search=['order_name']`）。

### 5.4 大列表视图缺搜索视图

`ta.bank.line`（63,939 行）、`ta.payment.claim` 均无 search view：银行流水无法按流水号过滤（全文搜索同样失效），只能翻页或表单直开。产品建议：为高频检索字段（流水号、客户）补 search view。

### 5.5 导游绩效 expense_count 跨月口径

报账日期 2026-10-03 与带团月 2026-11 不同月时，绩效行 `expense_count=0`（按报账单自身日期月份过滤）但成本已计入 cost_total。口径需产品确认（按带团月归属 vs 按报账月归属）。

### 5.6 供应商账单日期=发团日

批3 的 `_create_supplier_bill` 以发团日（2026-11-01，未来日期）作为 invoice_date，仿真付款日 2026-10-03 早于账单日。对付款视图与总账无影响，仅提示：未来日期账单在会计期间筛选时可能出现「未来凭证」观感。

### 5.7 UI 交互：订单报名名单行内下拉

UI 驱动段（A 脚本）中报名名单行内 kind 下拉选择不稳定（儿童单价联动需回填）。业务方法层（ORM 同源调用）核对正确；建议安排一次人工 UI 复核订单行编辑交互。
